# kube-agent 文档治理规则

> 最后更新：2026-06-12  
> 目的：让当前项目文档既能服务开发，也能服务学习和会话恢复。

## 当前真相源顺序

当文档之间出现冲突时，按以下顺序判断当前状态：

1. 当前代码和测试结果。
2. `codex-memory/kube-agent/current/RECOVERY_STATUS.md`。
3. `docs/PROJECT_MISSION_AND_MEMORY.md`。
4. `docs/AGENT_ARCHITECTURE_AND_TECHNICAL_LEARNING.md`。
5. `CHANGELOG.md`。
6. `docs/INDEX.md`。
7. 早期 `README.md`、`ROADMAP.md`、`docs/v3.1/**` 和历史审计波次。

## 文档分类

| 分类 | 说明 | 处理策略 |
|---|---|---|
| 当前维护 | 直接指导当前 Phase 1 顶级 Agent 开发和学习。 | 每个有效切片后同步更新。 |
| 当前参考 | 当前架构/治理仍需要，但不一定每次切片都更新。 | 相关能力变化时更新。 |
| 历史审计证据 | 已完成波次、审计报告、会话快照、旧计划。 | 保留路径；除非引用扫描通过，不删除。 |
| 二期参考 | NIM/HPC/Slurm/BCM 相关文档。 | Phase 1 暂停，只保留历史和二期准备价值。 |
| 需刷新 | README、ROADMAP 等仍有旧进度描述。 | 后续单独切片刷新，避免混在代码注释批次里制造大 diff。 |

## 清理规则

1. 不删除恢复记忆目录中的文件，除非明确确认它不是恢复链路的一部分。
2. 不批量移动 M5.21 波次文档。它们数量多、引用多，应该先做引用扫描和归档计划。
3. 对明显过时但有学习价值的文档，优先在 `docs/INDEX.md` 降权或标记历史参考。
4. 对当前主线文档，优先保持短入口、强索引、少重复；详细学习内容放入架构学习文档。
5. 对二期暂停范围，文档可以保留，代码和运行时能力不继续打开。

## 后续建议

1. 刷新 `README.md` 的技术栈、端口、当前状态和 Phase 1/Phase 2 边界。
2. 刷新 `ROADMAP.md`，把早期 M2/M4/M5.20 叙述改成“历史路线图 + 当前主线链接”。
3. 建立 `docs/archive/README.md`，然后分批移动早期 M4/M5.4-M5.20 审计文档。
4. 为 M5.21 NIM/HPC/Slurm/BCM 文档建立二期索引，而不是删除。
5. 在每批中文注释完成后同步更新 `docs/INDEX.md` 和 `codex-memory` 镜像。
