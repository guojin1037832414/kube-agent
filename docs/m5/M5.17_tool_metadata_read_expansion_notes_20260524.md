# M5.17 专家会诊与执行记录（草稿）

> 时间：2026-05-24
> 阶段：M5.17 Tool HTTP/风险元数据第四批基础设施 GET/READ 扩面

## 1. 会诊结论

- 安全专家：本批只选择纯 `httpClient.get(...)`、不触发写入/删除/审批/下载导出、且不属于 RBAC/LDAP/用户/组织/配额敏感管理域的基础设施查询 Tool。GET 不等于 READ，本批 READ 是经人工确认的免确认白名单。
- 源码契约专家：必须为每个 Tool 精确声明 `apiEndpoints`，并新增 endpoint 精确白名单测试，防止路径被“按名字猜测”写错。
- 架构专家：MCP/Memory/Observability 需要建立在稳定 Tool 风险元数据之上；当前继续扩面 READ 白名单更符合 M5 安全底座优先级。

## 3. 风险边界

- 本批含节点、Pod、Deployment、GPU、Slurm 等基础设施运行态信息，会暴露拓扑和资源状态；按 READ 放行的前提是 org 级隔离与后端权限仍然生效。
- `resource_preset_list` 会暴露可选资源规格，但不改变资源状态；如后续发现后端返回价格/账户敏感策略，可升级为敏感 READ。
- RBAC、LDAP、用户、组织、配额、文件上传/下载、审批、创建/删除/停止/扩缩容仍保持 UNKNOWN 或高风险治理，不纳入本批。
