## 三、已确认技术决策

| # | 决策项 | 结论 |
|:---:|------|------|
| 1 | ReAct 路线 | 采用手写 ReAct 循环，不依赖框架 ReactAgent |
| 2 | 框架 ReactAgent | 因 outputKey 写入 AssistantMessage 污染、版本漂移、条件边解析不可控，不作为主线 |
| 3 | Tool 参数契约 | 以 `ToolParameterSpec` 为唯一参数 truth source，schema/inputSchema/normalizer/prompt 共享 |

| 6 | 下一步主线 | 继续小批量扩展 ToolParameterSpec + 清理 URL 拼接 + ReAct 多步成功 E2E |

## 四、ReAct 当前真实状态

专家会诊推荐的手写 ReAct 路线已落地。当前 ReAct 不再是待办项，而是已进入 live Graph 路径：

```text
AtlasBrain -> DELEGATE_REACT -> react_node -> ReActEngine.runWithEvents()
```

已具备：

- Thought / Action / Observation 循环骨架。
- SSE 生命周期事件输出。
- token / orgId / conversationId 上下文透传。
- 目标资源不存在早停。
- 运行期事件 Sink 隔离，避免 Graph State 序列化污染。
- ReAct Prompt 动态工具目录。
- Tool 参数契约接入第一阶段。

仍需继续：

- 真实存在资源的多步成功路径 E2E。
- Prompt 长度预算和按 agent/意图裁剪工具目录。
- Tool Schema 覆盖更多高频查询/诊断 Tool。
- Plan/Execute/Reflect 完整循环。

## 六、下次恢复后立即执行清单

恢复 session 后按以下优先级推进：

1. **URL query 专项清理**
   - 扫描所有 `path += "?"`、`?name=`、`?chart=`、`?keyword=`。
   - 统一改为 query map。
   - 编译、E2E、日志验证不出现 `%253F`。

2. **ToolParameterSpec 第二批**
   - 优先 detail/query/diagnose 类。
   - 推荐候选：`pod_status`、`pod_query`、`deployment_query`、`event_query`、`helm_chart_*`、`image_detail_by_name`、`file_select_storage`。

3. **ReAct 多步成功路径 E2E**
   - 不只验证 target-not-found。
   - 选择真实存在资源，验证 `think -> act -> observe -> final`。

4. **Prompt 长度预算**
   - ReAct Prompt 不应一次塞入所有 109 Tool 完整 schema。
   - 需要按 agent/intent/context 裁剪。

5. **文档持续同步**
