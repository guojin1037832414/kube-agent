## 终极目标

`kube-agent` 不只是一个生产级 Agent 项目，也是一个 Agent 开发学习项目。目标是让项目拥有者通过真实工程实践，从 Agent 初学者成长为能设计、审计、实现顶级 Agent 的开发者。

一期目标不是“能对话的 MVP”，而是在 `kube-manager` / `vue-kube-manager` 基座能力之上交付顶级 Agent Core：

- 安全边界清晰。
- Tool / MCP / kube-manager 外部出口可治理。
- Graph / ReAct / Plan 编排可解释、可测试、可恢复。
- Memory/RAG、Eval、Observability、Audit 具备证据链。
- 多 Agent / 多专家审查先以证据和读模型落地，再逐步考虑运行时 handoff。
- 代码、测试、文档、恢复记忆都带有中文教学价值。

用户已明确：NIM / HPC / Slurm / BCM 推迟到二期，只是暂停这些专家域插件，不降低一期对顶级 Agent Core 的要求。

## 当前安全边界记忆

- `/api/agent/**` 当前已从临时 permitAll 收敛到 authenticated/admin 保护路径。
- Observability、Eval、Memory/RAG、Top-tier、MCP governance 目前主要是 admin-only 读模型；Memory summaries 是 authenticated 用户级摘要接口。
- MCP 只开放 admin-only 只读 Manifest/governance，不开放 runtime `tools/call`，且阻断二期域导出。
- A2A 目前是 provenance / compatibility / review 证据，不开放 runtime handoff。
- Memory/RAG 目前是契约、证据读模型和 caller-submitted bounded summary；retrieval prompt influence、vector store、embedding/reranker/GraphRAG runtime 仍关闭。
- Eval 目前有 admin-only deterministic replay/eval 入口和 gate evidence；CI blocking、LLM eval、Memory/RAG retrieval eval runtime 仍需 reviewed trace evidence。
- kube-manager 高风险写操作默认 fail-closed，必须具备 HITL、幂等、durable audit prewrite、post-write readback、release gate 和恢复记忆证据。
