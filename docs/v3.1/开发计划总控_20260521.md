## 0. 计划使用规则

本文件是从 2026-05-21 开始的新一轮推进总控文档，用来替代零散口头计划，不替代 `PROJECT_ATLAS_V3.md` 总纲。

后续执行必须遵循：

1. **专家会诊前置**：重大架构/修复/编码前必须先会诊或复用已完成的有效会诊结论。
2. **先实验再铺开**：先在 ReAct 主链路小样本验证，再扩展到更多 Tool/Agent。
3. **TDD 闭环**：行为变化优先写测试，先红灯，再绿灯。
4. **每完成一个子阶段更新本文件**：更新状态、完成项、测试结果、风险、下一步。
5. **每完成一个功能闭环**：测试通过 → Review → 根因/方案分析 → 更新 `docs/REVIEW_LOG.md` → 持续学习总结。
6. **每个大模块完成后再和哥哥对齐**：小阶段中间不反复打断，除非出现高风险阻塞。
7. **提交与双推**：每个可独立验证阶段中文 commit，并推送到 GitLab `origin` 与 GitHub `github`。
8. **代码注释**：所有新增 Java 类、方法、关键逻辑必须有详细中文注释。
9. **文档同步**：架构或路线变化必须同步更新相关文档。

## 5. 后续里程碑摘要

### 5.1 M4.3 Tool Schema-First 标准化

目标：让 ReAct 主链路 Tool 都具备统一参数契约，模型不再猜字段名。

要求字段：

```text
name
description
category / agentDomain
readOrWrite
riskLevel
parameters
requiredParameters
examples
outputSchema / errorSchema（逐步引入）
```

验收：8~15 个核心 Tool 完成 `getParameterSpecs()` 与 normalizer/Prompt contract 测试。

### 5.2 M4.4 Prompt 裁剪 + 动态 Tool 注入

目标：解决 109 Tool 全量暴露导致 Prompt 膨胀和误选 Tool。

机制：

```text
任务类型 -> Agent Domain -> Tool 白名单 -> ReAct Prompt
```

验收：候选 Tool 从 109 缩到 3~10，Prompt token 明显下降，主链路成功率不下降。

### 5.3 M4.5 Observability 最小闭环

目标：每次失败能定位到具体阶段。

事件字段：

```text
request_id
session_id
user_query
route_result
selected_domain
selected_tools
prompt_version
tool_schema_version
react_steps
tool_args
tool_result_summary
error_type
latency
```

错误类型：

```text
ROUTING_ERROR
TOOL_SELECTION_ERROR
PARAMETER_ERROR
TOOL_EXECUTION_ERROR
OBSERVATION_PARSE_ERROR
FINAL_ANSWER_ERROR
HITL_BLOCKED
TIMEOUT
```

### 5.4 M5.0 HITL C 方案治理

目标：写操作必须进入：

```text
生成计划 -> 风险分级 -> 人工确认 -> 执行 -> 审计
```

第一批建议实验：`scale deployment`，不要先做 delete。

强制原则：执行层强制校验，不能只靠 Prompt。

### 5.5 M5.1 6 Agent 逻辑分治

先逻辑分治，后物理拆分：

```text
Tool 标注 agentDomain
Router 选择 domain
Prompt 按 domain 裁剪
Tool 按 domain 注入
```

六类：

| Agent | 职责 | 安全策略 |
|---|---|---|
| QueryAgent | 查询资源和状态 | 只读 |
| DiagAgent | 故障诊断 | 只读 + 建议 |
| DeployAgent | 部署/扩缩容/回滚 | HITL |
| RBACAgent | 用户/权限/角色 | 强 HITL |
| StorageAgent | PV/PVC/存储 | 强 HITL |
| NetworkAgent | Service/Ingress/网络策略 | 中高风险 HITL |
