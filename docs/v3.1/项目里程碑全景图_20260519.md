## 四、未来详细实施计划

### 阶段一：架构解耦（预计 3-4 周）

#### 4.1 ReAct 多步推理引擎（第 1-2 周，🔴P0）

**目标**：实现「先思考 → 再执行 → 再观察 → 再决定」的闭环

**产出文件**：
- `react/ReActEngine.java` — 主引擎入口
- `react/ThoughtChain.java` — 思考链管理
- `react/ActionExecutor.java` — Action 执行器
- `react/ObservationCollector.java` — 观察结果收集
- `react/ReactContext.java` — ReAct 上下文

**技术方案**：
1. 手写 ReAct 循环（不依赖框架），基于 Spring AI ChatClient
2. 支持 max_iterations=5 的自动终止
3. 每种 Agent 内部可独立运行 ReAct（如 DiagAgent 的「查日志→定位→修复」三步）
4. 思考过程通过 SSE `thinking` 事件流式输出到前端

**对接方式**：
```
AtlasBrain.decide() → 判断 need_react → ReActEngine.execute() →
  while (step < max_steps):
    think → call_tool → observe → loop or finalize
  → 最终结果返回 AtlasOrchestrator
```

#### 4.2 六 大 Agent 独立拆分（第 2-4 周，🔴P0）

**目标**：每个 Agent 独立目录、独立职责、独立可测

**产出文件**：
```
agent/
├── core/
│   ├── AtlasAgent.java          # Agent 抽象基类
│   ├── AgentContext.java        # Agent 上下文
│   └── AgentResult.java         # Agent 执行结果
├── query/
│   └── QueryAgent.java          # 资源查询/状态查看/信息检索
├── diag/
│   └── DiagAgent.java           # 故障诊断/日志分析/异常排查
├── deploy/
│   └── DeployAgent.java         # 应用部署/服务创建/配置下发
├── rbac/
│   └── RBACAgent.java           # 权限管理/用户角色操作
├── storage/
│   └── StorageAgent.java        # 存储卷/PVC/快照管理
└── network/
    └── NetworkAgent.java        # 网络配置/带宽策略/域名
```

**重构路线图**：
1. **先建骨架**：创建 `AtlasAgent` 基类 + 接口契约
2. **逐个迁移**：从 AtlasBrain 中剥离对应职责到各自 Agent（每次 1-2 个）
3. **AtlasBrain 瘦身**：最终 AtlasBrain 只做「意图→Agent 路由」，不做具体执行
4. **测试保证**：每迁移一个 Agent，跑通对应的 E2E 用例

#### 4.3 MCP Server 集成（第 3-4 周，🟠P1）

**目标**：让外部 Agent/系统可以通过标准 MCP 协议调用我们的 Tool

**产出文件**：
- `tool/mcp/AtlasMcpServer.java` — MCP Server 主入口
- `tool/mcp/ToolMcpAdapter.java` — Tool→MCP Tool 适配层
- `tool/mcp/McpTransportConfig.java` — 传输配置

### 阶段二：HITL + 安全治理（预计 2-3 周，🔴P0）

#### 4.4 HITL C 方案完整实现

**目标**：高危操作命令式确认，普通操作弹窗确认

**产出文件**：
```
hitl/
├── HITLGuard.java              # HITL 守卫：拦截所有执行路径
├── ConfirmationService.java    # 确认服务：管理确认状态机
├── RiskClassifier.java         # 风险分级器：P0/P1/P2/P3
```

**交互流程**：
```

用户: "确认删除production"
Agent: → 执行删除 → 返回结果
```

**前端配合**：SSE 新增 `hitl_confirm` 事件类型，前端渲染确认输入框

#### 4.5 操作审计日志

**产出文件**：

### 阶段三：体验优化（预计 2 周，🟠P1）

#### 4.6 流式润色接入 SSE（polishStream）

**目标**：用户看到 LLM 逐字打字效果，而非整块输出

**方案**：
1. `polishStream()` 返回 `Flux<String>`
2. AtlasOrchestrator 将 `Flux` 转为 SSE `data:` 逐行发射
3. 前端：`eventSource` 逐字追加到 DOM

#### 4.7 Token 成本优化

**方案**：
1. **高频查询缓存**："所有部署状态"等常用查询结果缓存 5 分钟
2. **短结果模板命中**：数据量 < 3 条直接走模板，不调用 LLM
3. **PolishMetrics 日统计**：每日 Token 消耗报表

#### 4.8 会话持久化（Redis）

**方案**：
1. 引入 `spring-boot-starter-data-redis`
2. `SessionStore` 实现类从 Caffeine 切换为 Redis
3. 后端重启后用户无需重新登录
