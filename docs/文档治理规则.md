# kube-agent 文档治理规则

> 最后更新：2026-06-12
> 目的：让当前项目目录足够干净，同时不牺牲长期学习、审计追溯和会话恢复能力。

## 真相源顺序

当文档之间冲突时，按以下顺序判断当前状态：

1. 当前代码、测试和配置。
2. `codex-memory/kube-agent/current/当前恢复状态.md`。
3. `README.md` 和 `开发路线图.md`。
4. `docs/项目使命与当前记忆.md`。
5. `docs/顶级Agent架构与技术学习地图.md`。
6. `变更日志.md`。
7. `docs/adr/**` 和 `docs/tech-stack/**`。
8. Git 历史中的旧报告、旧会话快照和旧 v3.1 文档。

## 当前目录保留标准

当前目录只保留能直接服务以下目标的文档：

- 新会话恢复。
- 当前 Phase 1 顶级 Agent Core 开发。
- Agent 架构学习和中文教学。
- 架构决策记录。
- 技术栈审计与先进技术引入路线。
- Tool / Auth 等仍被代码和开发流程直接使用的规范。

不再把“每一轮历史波次报告”放在当前 docs 树里。历史可追溯不等于当前目录必须堆满历史。

## 删除标准

满足以下条件之一的文档可以从当前目录删除：

- 状态明显停留在旧 M2 / M4 / M5.20 / M5.21 阶段，且不再是当前入口。
- 内容属于 NIM / HPC / Slurm / BCM，而这些已经暂停到 Phase 2。
- 同一主题已有更新版本，旧版本只会误导。
- 只是一次性审计报告、会话快照、临时 review log 或迁移过程记录。
- 已经可以从 Git 历史或 `codex-memory` 恢复。

删除前要确认不删除：

- `codex-memory/**`
- 当前 ADR
- 当前技术栈主文档
- `PROJECT_MISSION_AND_MEMORY`
- `AGENT_ARCHITECTURE_AND_TECHNICAL_LEARNING`
- `README`
- `ROADMAP`
- `CHANGELOG`
- 仍被代码、测试或开发流程直接引用的规范。

## Phase 2 文档规则

NIM / HPC / Slurm / BCM 是二期范围。相关历史文档可以从 Git 历史或恢复记忆中读取，但当前 Phase 1 文档不再把它们作为开发计划入口。任何重新打开这些能力的动作，都必须先新增 Phase 2 计划、风险边界、测试证据和 release gate。

## 切片完成后的同步规则

每个有意义切片完成后：

1. 更新 `变更日志.md`。
2. 更新 `docs/项目使命与当前记忆.md` 或 `docs/顶级Agent架构与技术学习地图.md` 中对应学习内容。
3. 更新 `codex-memory/kube-agent/current/当前恢复状态.md`。
4. 镜像关键文档到 `codex-memory/kube-agent/current`。
5. 运行对应测试或至少 `mvn -q "-DskipTests" validate`。
6. 提交并推送。

## 这次清理后的阅读方式

平时只需要从 `README.md`、`开发路线图.md` 和 `docs/文档索引.md` 进入。要恢复上下文时读 `codex-memory/kube-agent/current/当前恢复状态.md`。要考古旧审计报告时用 Git 历史，不再让当前 docs 根目录承担历史仓库职责。
