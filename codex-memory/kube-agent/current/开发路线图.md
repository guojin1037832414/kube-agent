# Atlas Kube-Agent 当前开发路线图

> 最后更新：2026-06-12
> 目标：一期就完成顶级 Agent Core。NIM / HPC / Slurm / BCM 只是二期暂停，不代表一期降级。

## 总原则

1. 先做安全、证据和可恢复，再打开运行时权力。
2. Java / Spring 继续作为 Phase 1 主控制平面；先进技术通过官方来源审查、兼容矩阵、测试证据和 release gate 引入。
3. 所有新增或修改代码都优先补中文教学注释，解释设计意图、输入来源、输出去向和禁止动作。
4. 每个有意义切片都要更新 `codex-memory/kube-agent/current`，运行校验，提交并推送。
5. 当前线程聚焦后端；前端由独立会话推进，但后端需要持续提供只读契约和学习文档。

## Phase 1 完成判据

Phase 1 不以“能聊天”为完成，而以下列条件作为顶级 Agent Core 的完成标准：

- 身份、权限、HITL、Tool、MCP、kube-manager outlet 的安全边界在代码、测试、文档和中文注释中一致。
- ReAct / Plan / Graph 能被解释、测试、恢复和审计，不依赖隐式 prompt 运气。
- Memory/RAG 和 Eval 有 reviewed trace evidence、source custody、privacy/tenant 边界和 release gate；caller-submitted 摘要不能直接成为 prompt 权威。
- 多 Agent 审查有角色、证据、审查轮次和 runtime 权力关闭说明。
- 前端只渲染后端 owned read models，不把按钮或布尔值伪装成权限、release 或成功。
- `codex-memory` 能让新会话恢复目标、当前状态、下一步和关键安全不变量。

## Phase 2 暂停范围

以下内容保留为二期插件/专家域，不在当前一期继续扩展运行时能力：

- NIM 创建和 NGC/NIM 凭据链路。
- HPC / Slurm 作业链路。
- BCM 资源分配链路。
- 与上述范围直接绑定的写入、审计、release 和运行时执行。

当前可以保留代码里的 fail-closed / HOLD / 只读证据和历史测试，但不新增一期 runtime authority，也不把这些域导出到一期 MCP manifest。
