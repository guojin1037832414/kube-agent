## 终极目标

`kube-agent` 不只是一个生产级 Agent 项目，也是一个 Agent 开发学习项目。目标是让项目拥有者通过真实工程实践，从 Agent 初学者成长为能设计、审计、实现顶级 Agent 的开发者。

一期目标不是“能对话的 MVP”，而是在 `kube-manager` / `vue-kube-manager` 基座能力之上交付顶级 Agent Core：

- 安全边界清晰。
- Tool / MCP / kube-manager 外部出口可治理。
- Graph / ReAct / Plan 编排可解释、可测试、可恢复。
- Memory/RAG、Eval、Observability、Audit 具备证据链。
- 多 Agent / 多专家审查先以证据和读模型落地，再逐步考虑运行时 handoff。
- 代码、测试、文档、恢复记忆都带有中文教学价值。

用户已明确：NIM / HPC / Slurm / BCM 推迟到二期，只是暂停这些专家域插件，不降低一期对顶级 Agent Core 的要求。

## 最近代码学习批次

### M5.85-4：中文注释 Batch 2

覆盖 Tool / MCP / kube-manager 执行边界：

- `SafeToolExecutor`
- `SafeToolExecutionRequest`
- `ToolRegistry`
- `ProtectedToolParameterFilter`
- `McpToolManifestService`
- `McpManifestController`
- `KubeManagerHttpClient`
- `KubeManagerHttpResiliencePolicy`
- `Batch2ChineseCommentContractTest`

学习重点：

- LLM、Plan、前端参数只是候选业务输入。
- token、orgId、userId、HITL marker、audit receipt、release decision、writeAllowed、trace 字段必须来自服务端可信证据。
- `SafeToolExecutor` 是进入真实 `BaseTool.execute` 的统一边界。
- MCP Manifest 是只读能力目录，不是 `tools/call` 执行授权。
- kube-manager HTTP 是真实外部网络出口，业务请求禁止透明降级到 sysadmin token。
- 读重试和写重试不是同一类风险。

- `AgentSecurityConfig`

- `HitlGuard` fail-closed，但它只是完整 Tool 安全链的一环。

## 当前安全边界记忆

- `/api/agent/**` 当前已从临时 permitAll 收敛到 authenticated/admin 保护路径。
- Observability、Eval、Memory/RAG、Top-tier、MCP governance 目前主要是 admin-only GET 读模型。
- MCP 只开放只读 Manifest/governance，不开放 runtime `tools/call`。
- A2A 目前是 provenance / compatibility / review 证据，不开放 runtime handoff。
- Memory/RAG 目前是契约和证据读模型，retrieval prompt influence、vector store、embedding/reranker/GraphRAG runtime 仍关闭。
- Eval 目前是 deterministic/read-model/gate evidence，CI blocking 和 runtime eval 仍需 reviewed trace evidence。
- kube-manager 写操作和写重试必须等待幂等、HITL、durable audit、post-write readback、release gate 和恢复记忆证据。
